# Soulmates Classic Playtest - October 2, 2026

## Status and Boundaries

Base: commit `0ca8716`, Soulmates 0.15.1. Local candidate: **0.15.2, Clear Targets**. This run used an isolated graphical tModLoader client with only Soulmates enabled, separate saves, and local Field Notes for its test fixtures. The regression probe was never enabled in this graphical client. No normal installation, original player/world, Git remote, Steam description, or Workshop upload was changed.

The operator played through the native game UI. The user supplied the character name because injected text entry was unreliable; creation, binding, gameplay interactions, and saving were then mouse-controlled. The graphical client was saved and exited through the native menus. Short injected clicks were sometimes missed, so a one-pixel mouse drag was used as a sustained click. These limitations are not evidence that the corresponding in-game buttons are broken.

## Real Client Setup

- tModLoader 2026.8.3.0, Terraria 1.4.4.9, windowed 1280x720 client area.
- A newly created Classic character, **Classic QA**, initially 100 life and 20 mana. Journey fixtures were excluded from pickup measurements because native player pickup competed too strongly with companion gathering.
- **The Dream of Fear**: native Small Classic Crimson world, seed `70169106`. This covered binding, gathering, direct mining, day/night combat, saving, and reloading.
- **Sour Front of Branches**: native Small Classic Corruption world, seed `864842239`. The same character and companion continued into this fresh daytime world for screenshots and resident interaction.
- No edited world, accelerated clock, generated screenshot, or staged fake game UI was used. Inventory was mapped to Mouse3 in this isolated client's configuration because brief injected key presses were unreliable.

## Confirmed Findings and Repairs

| Area | Observed finding | Candidate repair and evidence |
| --- | --- | --- |
| Direct world orders | At effective 120% UI scaling, the mining outline selected a different tile from the cursor. | Derive world position from raw input through the inverse world-view matrix instead of using `Main.MouseWorld` inside scaled UI hooks. In actual play, the corrected dirt order mined 24 tiles and completed its job. |
| Cargo visibility | An empty equipment Pack opened even when Resources contained drops. The native Resources hover label covered the first item slots. | Open the first populated compartment, show compartment counts, and fit tab/page hover text into the cargo header. Existing gel, acorns, dirt, and a lens were visible after reload. |
| Resident awareness | Emotes were previously noticed only during a companion-initiated visit. | Nearby idle companions can begin a short response to a resident's native emote, with a 45-tick reply delay, relationship memory, and existing social priority/cooldown rules. Real Guide exchanges and native bubbles were captured; spontaneous initiation outside an existing visit was separately exercised by the engine probe. |

The pickup transaction itself was not rewritten. The initial apparent blank-resource finding was a display/hover problem, not confirmed lost cargo. The earlier local filename `06-classic-resource-tab-blank-bug.jpg` describes that initial hypothesis and must not be treated as evidence of a data-loss bug.

## Observed Gameplay

- Soulcore right-click from the inventory opened the creator. Binding AETHER consumed exactly one Blank Sigil, retained the reusable Soulcore, and produced a working companion Sigil.
- The custom Soulkin rendered and moved. Repeated visible guardian bolts hit real slimes for 8 damage. One night session recorded 54 attacks and three 5-life heals.
- Native tree shaking produced drops. The player mined dirt with a native pickaxe; the companion recognized that material. The corrected explicit order then mined 24 real dirt tiles and collected their drops.
- The first cargo transaction collected three gel, seven copper coins, and one acorn. Withdrawing one gel and then returning the remainder yielded the measured original quantities. Depositing the player's selected three-gel stack removed it from the player and stored it in cargo.
- Candidate cargo survived saving, reloading, a normal player death, and entry into the second world. Level 3 to 4 progression increased the observed resource limit from 150 to 200 per type.
- The wallet displayed 3 silver and 96 copper. A single copper withdrawal changed its balance from 396 to 395 and returned one coin. Later automatic pickups increased the balance again.
- Player and companion wheels opened separately. The player's native-emote crescent and heart action worked, with a native player bubble and companion reply. The companion bag opened the inventory interface.
- Guide Joe and AETHER exchanged native emotes. Local records contain two `resident_emote_reply` events for NPC type 22, including emotes 139 and 69. The real screen showed personality-aware dialogue and a later remembered-face greeting.
- The creator's Miner control changed the talent without also randomizing the draft. Bunny, Blue Slime, Bird, and Squirrel previews appeared. This was a preview check, not a full world-animation test of each form.
- A deliberately dropped Copper Shortsword was reclaimed by the player (`player_pickup`, item type 3507), not the companion. That attempt is not counted as a successful companion pickup test.

There were ordinary player deaths during night testing with AutoPause off, including while UI work kept the character stationary. No graphical runtime crash was observed. This is not an AFK-survival or combat-balance pass.

## Remaining Work

- Live multiplayer, latency/reconnects, concurrent companions, third-party mods, every talent, and complete progression were not graphically tested. Server/client authority fixtures are not a substitute for a real multiplayer session.
- Mailbox typing, every native furniture interaction, digging modes, planting, insect catches, and long-running automation need additional hands-on coverage. Tree shaking was observed; this does not establish living-branch pruning, which is not implemented.
- The new spontaneous NPC response outside an existing visit passed engine fixtures; actual Guide exchanges establish dialogue/rendering, not an isolated timing measurement of that initiation branch.
- Coin-slot hover text is still long. Native creator previews are enlarged and some tint/filter combinations deserve another visual polish pass. Rapid clicks on the moving companion can miss its body hit area; no reproducible code fault was established from those misses.
- Native player pickup still competes with nearby deliberately dropped items, even in Classic. A failed controlled companion pickup cannot be inferred solely from an item disappearing near the player.
- Before release, decide whether to install the candidate, run the remaining interactive cases, and update release metadata with only this patch's notes. The public version remains 0.15.1; this report does not authorize or claim a publication.
