# Soulmates 0.14.0 Client Control Pass

Date: 2026-10-01. Local prepared alpha, not a public release.

## Isolation

An independent tModLoader save directory contained copies of the earlier Journey test character `sqa` and test world `Red Dab of Annoyance`. Only Soulmates was enabled; the engine regression probe was not present. Original player/world files were not used for gameplay or overwritten.

The first client ran tModLoader 2026.7.3.0; after restarting, the installed runtime reported 2026.8.3.0. The second client loaded Soulmates 0.14.0 successfully. Final packaging and engine checks use the updated runtime.

## Observed In The Actual Client

- Summoned the existing AETHER Sigil; the Soulkin sprite and normal native emotes rendered.
- Right-clicked the player with a normal sword selected: the separate root wheel appeared with Emotes, Point, and Mailbox.
- Clicked Emotes: Terraria category icons expanded into a crescent.
- Closed the player wheel through its native X.
- Right-clicked terrain: no world menu opened. Right-clicked clear air: the four-tool Point wheel opened.
- Right-clicked an open world wheel: it changed to three Area-work choices; another right-click returned to Point.
- Selected Look, then clicked a tree: AETHER described a forestry opportunity without performing a work order. The Look tool remained active afterwards.
- Right-clicked the active Look tool: it returned to Area work. X returned to normal gameplay.
- Existing Always-forestry behavior was seen shaking trees, with normal visible fruit drops. This was observation, not a measured forestry/cargo conservation test.

## Found And Fixed

The first pass showed a moving companion under the cursor replacing the open world wheel with its own menu. `PreHoverInteract` now respects captured Soulmates input. Engine tests exercise that guard for wheels, prompts, and direct targeting. In the second client, the world wheel cycled without being replaced when right-clicked near the companion; movement makes exact pixel-overlap coverage limited.

Normal speech could cover an open wheel. The final code hides regular speech while the wheel is open; an engine assertion covers that visibility rule. Look/Point now consistently use binoculars, and area gathering uses a loot magnet instead of a tree. These last display changes were made after the client captures and have not been visually retested.

## Limits

This is a bounded mouse-control and rendering pass, not complete progression or live multiplayer testing. Short injected Escape presses were unreliable, so a clean Save & Exit cycle was not verified; copied test clients were closed through their title bars. No claim is made that every emote, talent, ore, combat case, forest action, or long-session behavior was manually exercised.

Automated engine tests separately cover cargo conservation, wallet operations, save/load, binary profile transport, attention fairness, pending target validation, directed forestry selection, and UI input ownership. Those checks do not render the interface or replace real multiplayer tests.
