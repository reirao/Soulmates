# Soulmates 0.19.6: Careful Repairs

## Result and Scope

The four reproducible correctness findings in the [0.19.5 audit](FULL-AUDIT-2026-10-03.md) are repaired in this local candidate. Personal questions no longer block already approved automatic work. The original audit remains historical evidence, not an erased or rewritten all-clear.

This pass preserves the earlier uncommitted 0.19.4/0.19.5 work and adds focused repairs. It introduces no new gameplay feature, generated artwork or external AI service. No normal client installation, character/world save, public description, Git commit/push or Workshop release was changed. The recorded installed baseline remains 0.19.5 and public baseline 0.19.3; public status was not rechecked.

## Repairs

1. **Cargo conservation.** `CompanionProfile.NormalizePack` no longer clamps saved quantities to a reduced native stack maximum. Available slots receive cloned legal stacks, preserving item metadata. If cargo is full, a legacy oversized remainder is deliberately retained internally until space or withdrawal is available. Excess reconciliation, individual withdrawal and unloading return only legal native stack sizes. An unavailable owner inventory leaves the remainder in cargo. This prevents new migration loss; it cannot reconstruct units already erased by an older build.
2. **Captured companion and storage identity.** Older mutating request families now carry the originally clicked profile GUID. Authority rejects a request after companion replacement. Storage withdrawals additionally carry a SHA256 fingerprint of the captured storage kind, index and native network item representation, including stack and modded network metadata; wallet requests include the captured balance. Changed views receive existing localized target-changed feedback and fresh profile state instead of taking another slot's contents. This fingerprint is a consistency check, not an authentication mechanism.
3. **Work-answer identity.** Each permission question receives a new GUID, synchronized in NPC ExtraAI. UI clicks, response packets and acknowledgement waits include the captured companion and question. Replaced, expired and duplicate replies cannot grant Always or start another target. Notifications only present already synchronized matching state; an old notification cannot resurrect a completed task. Target/context validation remains in place.
4. **Actual mining observations.** A native `On_Player.PickTile` hook records the real target before the original mining operation can remove a one-hit block. Multiplayer sends owner-bound target/tool observations before native removal. Authority validates carried binding, companion distance, native tile reach, current tool identity/use, pick power, tile eligibility and native kill checks. Material learning never reads or mutates server-local mouse coordinates. Observation cooldowns are per player; this remains bounded rule-based learning.
5. **Nonblocking personal questions.** Already Always-approved automatic opportunities may proceed while a personal question awaits an answer. The question remains answerable during that approved work. Ask/Never permissions are not bypassed, new permission prompts wait, and combat, explicit jobs, Stay, recovery, binding and range rules remain authoritative.

Questions are checked both with Always-approved gathering and Ask work still waiting for consent.

Initial expanded runs exposed incomplete old UI fixtures and cooldown carryover between independent scenarios. Fixtures now capture the same profile/token fields as production UI and reset attention only when starting a fresh eligible scenario. No production cooldown was removed to make a test pass.

## Remaining Limits

No graphical playthrough, screenshots, connected host/client session, progression run or long-session balance test was performed. Real multiplayer packet ordering, mining control synchronization and latency still need a connected test. Native panel geometry checks use a measurement font and do not establish visual quality. Safety deliberately rejects an outdated storage click during concurrent collection; refresh and retry rather than silently taking another item.

This repairs the reproduced findings, not every possible bug. The historical requirements matrix still distinguishes bounded implementations from open requests such as native extra vanity-pet summons, wall deconstruction and trap warnings. No roadmap or release promise is added here. Private player journals and typed feedback are not included in these artifacts.
