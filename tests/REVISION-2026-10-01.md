# Soulmates Full Revision - October 1, 2026

## Status and Boundaries

Base: commit `11bd554b8c19807eb49c13d93a71c7fc0c710ec5`, Soulmates 0.15.0. Prepared patch: 0.15.1, Careful Company. No commit, push, Steam upload, description edit on Steam, or installation change was performed in this revision. User saves and feedback files were read only; the screenshot gallery remains unchanged.

The review covered input ownership, the three wheels and initiative choices, work and pickup, equipment/resources/wallet, owner and Sigil lifecycle, combat/healing, forestry and insect catches, social persistence, feedback privacy, packet boundaries, creation transactions, localization, and release metadata. Findings were fixed where reproducible; this is not a claim that every path or third-party mod combination has been exhaustively tested.

## Confirmed Findings and Repairs

| Area | Finding | Repair |
| --- | --- | --- |
| Multiplayer recovery | Native life-state and cosmetic heal messages do not apply the intended recovery to the owning client. Carried mana recovery and server-applied potion/food buffs also lacked owner delivery. | Bounded native SpiritHeal deltas, owner-specific mana recovery, and explicit native player-buff messages. Test the native receiving handlers as well as packet construction. |
| Gathering | The check for capacity-blocked loot reused the capacity filter, making it impossible to report drops excluded by that filter. Directed fetches could also report a lost target when capacity filled. | Separate eligibility/identity from capacity. Report full cargo when the target is still present, and reject pickup mutations in client authority mode. |
| Sigil persistence | A companion could continue changing the world after its persistence item left the inventory, including a queued multiplayer command before the next AI tick. Cursor-held single-player Sigils were not found. Perk XP was awarded after saving the profile. | Require a carried binding before authority-side work and mutating requests, reject dead-owner commands, retain cursor binding in single-player, and persist after the XP award. |
| Input | Native chat/sign/chest editors and captured Soulmates interfaces did not consistently stop global wheel shortcuts or automatic choices. | One typing/capture guard for shortcuts, deferred self-wheel opening, companion hover, and automatic initiatives. |
| Initiative acknowledgement | Client state can still contain an answered question until the next synchronized update. | Wait by profile ID and initiative kind until acknowledgement, a companion change, or a bounded timeout. |
| Summoning | A full NPC pool returns an out-of-range sentinel index. | Check the result before dereferencing, reject client-side spawning, and show a localized failure. |
| Combat | An invulnerable but otherwise chaseable enemy could keep the defense target locked. | Reject such threats while retaining the deliberate target-dummy exception. |
| Feedback | Some automatic events included exact tile coordinates despite the privacy wording. Notes accepted 360 characters but were truncated to 180 later. | Remove coordinate fields and filter them centrally, use a shared 360-character limit, and clarify that typed notes preserve their contents. Old logs are untouched. |
| Packet boundaries | Truncated payloads and wrong-direction messages could reach handlers before validation. | Reject invalid direction, sender, empty streams, and minimum-length violations; catch only expected malformed-data exceptions. |
| Feedback overhead | Cargo observation allocated two containers and rechecked the opt-in file repeatedly. | Reuse buffers and cache opt-in until an explicit change or unload. No timing benchmark is claimed. |
| Packaging | The installed packer copies `icon_small.png` for template comparison, then converts the same stream without rewinding it. | Exclude that optional mini-icon, retaining its source and the full mod/Workshop icons. Verify package contents and rebuild without the image-type warning. |

## Verification

- The original static/math suite passed 2,335 assertions before editing.
- New counterexamples run against the original package exposed 67 assertion failures across input, pickup authority, cargo status, malformed packets, privacy, and note length. This is not a count of 67 distinct bugs.
- The revised suite passes 10,081 isolated engine assertions and 2,340 static/math assertions, with zero failures. Translation checks cover 612 English/German keys and 327 source references. Invalid encoded string lengths are included alongside truncated and wrong-direction packet cases.
- Existing engine coverage retains cargo conservation, mixed types, reserve limits, coin conversion, huge wallet balances, legacy migration, clone independence, save/load, binary transport, safe mining/forestry, exact native catches, relationships, emote meanings, and scheduler fairness.
- New native projectile tests exercise repeated shots, cooldowns, correct target and companion ownership, base damage, client-side rejection, server-owned shots, facing a target while retreating, Stay defense away from the owner, duplicate retirement, and removal of only the recalled companion's bolts.
- Healing checks run the production helper and actual native SpiritHeal and AddPlayerBuff receive handlers. Mana checks exercise the mod's owner-side receive handler with positive, negative, and oversized values.
- Input coverage uses real engine flags and production guards, not simulated physical key presses. Geometry tests run production arithmetic without a rendered UI.
- Builds and checks use a separate workspace runtime and save directory, with installed tModLoader 2026.8.3.0 dependencies. Runtime DLL SHA-256: `FCC6A9624B12191BE4A15D714A3675440911FEB8C1D374642AB1FD686F0DA0A5`.
- Both MSBuild and the native tModLoader compiler without `-eac` complete with zero errors/warnings; native packaging no longer emits the image-type warning. `git diff --check` is clean. Prepared English/German Workshop descriptions are 6,193 / 6,677 UTF-8 bytes, below the 8,000-byte limit.

The final native-compiled package and raw check outputs are stored locally in `outputs/revision-0.15.1`. After refreshing the release wording, `Soulmates.tmod` is 1,308,421 bytes; SHA-256: `38FDD3B45E2B4CA07CF03C4F208027AC91DB9B1C7D5691022C9EB072A34BD247`. The engine suite was rerun against this exact package: 0.15.1, 10,081 assertions, zero failures. The static suite also passed again. This folder is ignored by Git; the probe is not part of the distributed package.

The probe runs after loader hooks and network IDs initialize, exits before loading a world, and is excluded from the distributed mod. Do not enable it in normal gameplay. Test fixtures restore replaced players, NPCs, items, projectiles, input flags, and feedback buffers. Combat-text slots are deliberately occupied during headless recovery tests to avoid exercising unavailable client fonts.

Two deliberately invalid encoded-string packets produce first-chance diagnostics in the isolated loader log; the packet boundary handles them and the tests complete successfully. These are not gameplay crashes. The combat fixture uses the native server player sentinel, 255, so server-spawned projectiles receive their intended AI ownership fields.

## Remaining Verification

- No new graphical client playtest or screenshot session was conducted for this patch. Check mailbox typing, vanilla chest/workbench interactions, wheel transitions, sprite direction, speech/emote overlap, and every native sprite form in actual play.
- Dedicated-server authority and native receiving handlers are checked in isolation with disconnected sockets. Real latency, host-and-play, reconnects, simultaneous clients, and long multiplayer sessions remain unverified.
- Complete Terraria progression, unusual third-party item hooks, modded food/potions, large resident histories in actual play, and long-session performance still need testing. Existing resourceful item use is not a claim of universal modded-item compatibility.
- The old image-type warning was traced to the installed packer's optional-mini-icon stream handling and removed by excluding that asset. The same unrewound-stream behavior appears in [official ModCompile source](https://github.com/tModLoader/tModLoader/blob/stable/patches/tModLoader/Terraria/ModLoader/Core/ModCompile.cs). No installed loader files were patched. Compact mod-list icon fallback still needs a graphical check; successful packaging and headless loading do not establish that every client image renders correctly.
- The isolated server reports denied `.tmod` registry association access under the sandbox. It continues and completes tests; this is separate from a mod runtime crash.
- This checkout contains inaccessible old pip temporary directories under `work`. The native packer enumerates directories before applying `buildIgnore`, so building directly through the canonical checkout can encounter those unrelated cache permissions. Verification packages a clean source-only `work/revision-source/Soulmates` staging folder, not the cache tree. No old caches or permissions were changed.

Before publication, install the prepared patch with tModLoader closed, retain a backup, run a real-client pass, and verify the uploaded binary's version. Steam update text must use only `changelog.txt`, never the accumulated development history.
